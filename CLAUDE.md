# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A smart-ticker kiosk appliance for a Corsair Xeneon Edge (2560×720 touchscreen): FastAPI backend pushing live data (markets, sports/fantasy, news, a weather suite incl. animated radar and NHC hurricane tracking, rocket launches, astro, Proxmox, ADS-B, Home Assistant) over WebSockets to a Chromium-in-cage display page, plus a LAN admin GUI. Production runs from `/opt/edge-ticker` as `ticker-backend.service` on `:8080`; this checkout is the dev copy.

## Commands

```bash
# Backend (Python ≥3.11; this box has no uv — use the venv)
.venv/bin/uvicorn backend.main:app --port 8081      # dev backend (8080 is prod)
.venv/bin/python -c "import backend.main"            # fast import check
.venv/bin/python -m pytest -q tests/                 # offline suite (~300 tests, ~4 s)

# Fixture mode: serve recorded payloads, poll nothing upstream (no collectors,
# no night scheduler/DDC, no HA bridge). The way to run a dev backend for display work.
TICKER_FIXTURE=scripts/fixtures/display_snapshot.json TICKER_DB=/tmp/dev.db FINNHUB_KEY= HA_URL= \
  .venv/bin/uvicorn backend.main:app --port 8081
.venv/bin/python scripts/layout_audit.py                        # every theme × layout × module, clip check
.venv/bin/python scripts/layout_audit.py --themes sovereign --modules proxmox --shots ~/shots

# Frontend (from frontend/)
npx tsc --noEmit        # typecheck (strict; runs over display/, admin/, shared/)
npm run build           # vite build → frontend/dist (served by the backend)
npm run dev             # hot-reload dev server, proxies /api + /ws to :8080 (prod!)

# Dev probes against a running backend (TICKER_URL, default http://127.0.0.1:8081)
.venv/bin/python scripts/smoke_test.py    # REST endpoints + display WS snapshot
.venv/bin/python scripts/unit_checks.py   # scheduler broadcast, display_state relay, stretch shaping

# Deploy (on the appliance; fast-forwards to origin/main — push first)
sudo bash deploy/update.sh              # verify + build beside the live bundle, switch, health-check
sudo bash deploy/update.sh --rollback   # back to the commit before the last update
```

`update.sh` changes nothing live until the backend imports, the frontend typechecks and the new bundle is built (into `frontend/dist.new`, swapped in whole); a backend that fails its health check after the switch is rolled back automatically. It also syncs changed systemd units and the udev rule (formerly only `install.sh` copied them). The whole script is one `{ … }` block because its own `git reset` rewrites the file bash is reading.

**Displays follow deploys on their own.** Every WS snapshot carries `build` (the hashed assets each built page links, `backend/build.py`); a production bundle whose document links a different set reloads itself (`frontend/shared/build.ts`, once per target build). A backend restart therefore moves the panel onto the new bundle at reconnect — the manual `reload` POST (and its race: sent before the kiosk reconnected, it reached nobody) is no longer needed. `update.sh` still sends one after the kiosk reconnects, for bundles that predate this.

Tests: `tests/` runs fully offline — `conftest.py` blocks sockets and scrubs credential env; upstream responses are recorded in `tests/fixtures/` (provenance in `conftest.py`; Launch Library is shared with prod at ~15 req/hr, so don't re-record casually).

`/display` and `/admin` on the backend serve `frontend/dist` (with `Cache-Control: no-cache`) — an unbuilt checkout returns a 503 explaining that, and the `/assets` mount is created **at import time**, so the first `npm run build` after starting a backend needs a backend restart before assets load. `npm run dev` proxies to `:8080`, i.e. **prod**, so dev-backend visual checks go through `npm run build` + `:8081/display`, not the Vite server. A rebuilt bundle reaches an open dev display only when it reconnects (restart the backend).

## Architecture

**Data pipeline:** each module is a backend `Collector` subclass (`backend/collectors/`, contract in `base.py`: `fetch()` upstream → `shape()` into a `ModulePayload` with `stage` dict + `tape` items) publishing to the in-memory `Bus` (`backend/state.py`), which fans out to all WebSocket clients (`/ws/display`, `/ws/admin` — same stream). Collectors never crash the app: failures re-publish the last payload with `stale=True` and back off (a restarted collector inherits the bus's last payload so it can still mark it stale); every sleep is floored at 5 s. A collector also declares `enabled_by_default` (stretch modules ship off so a fresh install runs only v1 modules) and `required_env` — missing env means the collector is skipped at startup, never errored; `/api/health` lists skipped collectors with the reason (`disabled`, `missing env: …`, `error: …`). Partial failures a collector survives (one feed of five, the sports schedule window) belong in `self.degraded` — they used to be debug-logged and invisible while health said ok (ESPN broke the sports window for ten days that way). Location-based collectors set `uses_location = True` (a location edit restarts them too). Backend discovery is automatic (drop a file in `collectors/`); the frontend needs three touchpoints per new module: import in `display/main.ts`, a `MODULE_LABELS` entry there (pane-header title), and the `STAGE_MODULES` list in `admin/src/tabs/modules.tsx` — and it stays invisible until it is also in `rotation.order` (and enabled). Add its keys to `config/defaults.yaml`: stored config is deep-merged over the defaults on load and on save (`db.with_defaults`), so existing databases pick new keys up (lists/scalars stored win whole). Code should still default gracefully (`.get(key, default)`, admin's spread-patch idiom `c.modules.x = { ...(c.modules.x ?? {}), key: value }`). Collectors with dynamic cadence mutate `self.interval` inside `shape()` (sports/fantasy live-vs-idle, launches near T-0).

**Config saves** (`backend/api/config.py`, `config_check.py`, `manager.py`): a `PUT` is validated before anything is saved — structural checks, then every enabled collector is *constructed* from it (the same path startup takes); failures return 400 with the offending keys. A saved config that crashed a constructor used to crash-loop the next boot with the admin GUI down. Saves are kept (last 20, `config_history` table) with one-click restore in the System tab. `CollectorManager.apply()` restarts only collectors whose `config_fingerprint()` changed (own module config, plus the shared location when `uses_location`); disabling a module stops it and broadcasts `module_removed` so its payload/tape leaves the screen.

**Frontend display** (`frontend/display/`, Preact-free vanilla TS): `main.ts` owns the WS client, rotation engine, and a **multi-pane stage** — layouts can show 1–3 consecutive rotation modules side by side (`panes` field in `LAYOUTS`). Each pane holds crossfading `.stage-layer`s plus a persistent `.pane-header`; `crossfade()` must only remove `.stage-layer` children. A change of view crossfades (themes animate it); a routine data refresh of the same view swaps in one frame via `quietRefresh()` once the new layer's images decode (a hidden `.pending` layer; map renderers build tiles in a rAF after attach, so images are collected a frame later). Renderer exceptions are contained per pane. While blanked, `html[data-idle]` pauses every CSS animation and module renders are deferred until wake. Module renderers register in `modules/registry.ts` (`renderStage`, optional `renderDetail`/`getDetailItem` for tap-to-expand). Open details freeze (panes skip re-render) — anything needing live refresh must render in `renderStage` (that's why live game mode lives inside the sports renderer, and the launches T-0 board inside that renderer). **Renderers have no teardown hook**: animation must be CSS (radar frame loop, ADS-B sweep) or a JS interval that clears itself when `!el.isConnected` (launches countdown). Tape items are static strings until the collector republishes — no client-side relative time. Cross-module data reaches a renderer via an exported setter fed by `main.ts` (`setWeatherAlerts`, `setSportsLiveMode`, `setLaunchSun`). Live events auto-pin via the edge-triggered `applyAutoFeature`/`clearAutoFeature` pair in `main.ts` (sports/fantasy/launches; opt-in per module via `modules.<id>.auto_feature`). The tape keeps its pixel offset across rebuilds (item counts change every ADS-B poll; restarting at 0 meant the tail of the tape never scrolled into view).

**Map modules** (weather_radar, hurricanes) share `frontend/display/slippymap.ts` — Web-Mercator math, tile mosaics, `fitView`, and fractional zoom (tiles at the nearest integer level, CSS `scale()` about the view center for the remainder; overlays inside the scaled container need `vector-effect: non-scaling-stroke`, crisp text chips go outside it at post-scale coordinates). They also share the `.radar-viewport`/`.radar-map`/`.radar-basemap`/`.radar-home` CSS plumbing.

**Appearance:** themes are CSS-variable bundles + a `data-theme` attribute; layouts are `data-layout` grid variants — both defined once in `frontend/shared/themes.ts` (shared by display and admin selectors) and applied by `applyAppearance()`. Structural elements used by only some themes (pane headers, weather location, HA overlay titles) exist in every DOM but are `display:none` until a theme reveals them — the existing themes must stay pixel-identical when adding such elements. `data-panes` on `<html>` lets module CSS adapt to narrow panes (single-column lists, row caps — stage layers are bottom-aligned, so oversized content overflows out the top).

**WS contract beyond module payloads** (full reference in `docs/api.md`; original design rationale in `PLAN.md`): both channels get the same `snapshot` on connect (modules + config + HA states + `display_state` + current `night` state + `build`) then a stream of `module`/`module_removed`/`config`/`control`/`ha_state(s)`/`ha_status`/`night` messages plus the event messages below. Traffic is not one-way — the display reports what it is showing back over the socket (`display_state`), the `Bus` caches it, and admin clients render that as a live preview, so changing the display's state shape breaks the admin preview. Each subscriber has a bounded queue (512) that **drops** messages for a slow client rather than backpressuring collectors. `NightScheduler` (`backend/scheduler.py`) re-reads live config every minute (admin edits apply without restart) and is **level-triggered**: it applies whatever brightness the current minute calls for whenever that differs from what it last applied (so startup and admin edits reconcile immediately), via `ddcutil setvcp 10 <level>` (20 s timeout), falling back to a software dim the display draws. Every change broadcasts `night` with a `software` flag, and the snapshot carries the current state — so night behavior is split across backend and display and must be checked on both. Full-screen takeovers lift the dim: camera alerts call `scheduler.boost()`, and the scheduler boosts itself for `weather_alert` broadcasts it sees on the bus (the display suppresses its software dim for both).

**Access guards** (LAN trust, no login): `backend/origin.py` refuses cross-site writes and WebSocket handshakes (Origin host ≠ Host), and `HABridge.call_service` only runs services from `CONTROL_SERVICES` on entities mapped in `config.ha` — the bridge holds a full-access HA token.

**On-demand detail proxies:** `backend/api/sports.py`, `backend/api/markets.py`, `backend/api/fantasy.py` (detail, plus `/fantasy/logo` and `/fantasy/player` image proxies) and `backend/api/adsb.py` (`/adsb/route`) curate ESPN/Finnhub per-item detail (win probability, standings, headlines, analyst ratings…) with small TTL caches; the display fetches them only on tap (`enrichDetail` pattern: render base synchronously, fetch, patch if `el.isConnected`). Never poll these.

**Events beyond module payloads:** the sports collector diffs followed-game scores between polls and broadcasts `sport_event` → full-screen celebration overlay (`celebrate.ts`: field scene → fireworks → scorer card; queued, tap-dismiss). HA alert entities ride the bridge's mapped-state broadcasts → tape items while matched + transition toasts. Score celebrations are throttled by a **sport-aware per-team cooldown** (`SPORT_COOLDOWN_SECONDS` in `sports.py`): short for discrete scoring (baseball/hockey, so every run/goal fires), long for basketball — the score-diff already fires only on an increase, so a blanket long cooldown silently drops legitimate runs. `POST /api/control {"action":"celebrate_test"}` replays a real Packers touchdown — note it's **football-only**, so it proves the overlay renders but exercises neither per-sport rendering nor the live score-diff path (a passing "test works" does not mean baseball works).

**External-API constraints (hard-won):** Finnhub free tier has no candles (sparklines are self-built from accumulated quote history, persisted to `data/markets-spark.json`) and no crypto REST (`-USD` symbols poll Coinbase's keyless API; Binance is US-geo-blocked); one Finnhub WebSocket per key (dev and prod fight over it — prod wins). Yahoo 429s this network. ESPN scoring plays: `scoringPlays[]` for football/hockey, `plays[].scoringPlay` for MLB; NFL plays carry no participant ids — scorer is resolved by earliest boxscore-name match in the play text. **MLB scoring plays carry `team:{id}` with no abbreviation — match the followed team's play by team *id*, not abbreviation (`latest_scoring_play(..., team_id=)`), or the celebration shows the opponent's scorer/play.** IPO-day quotes have no previous close — measure against the open. RainViewer radar tiles cap at **z7** (higher zooms return "Zoom Level Not Supported" placeholder PNGs that still 200 — check for the 4-bit-colormap tile, not the status); the display upscales radar over a sharper Esri dark-gray basemap (keyless; Carto's keyless tiles are watermarked "API KEY REQUIRED" since 2026) via `frontend/display/slippymap.ts` fractional zoom. ESPN's site scoreboard rejects `dates=YYYYMMDD-YYYYMMDD` ranges with a 400 since 2026-09-15 — the sports schedule window fetches one `dates=YYYYMMDD` per league per day (settled days cached). Finnhub REST takes the key in the `X-Finnhub-Token` header (never the `token` query param: httpx logs request URLs, which is how the key ended up in the journal; httpx is now logged at WARNING). Launch Library 2 free tier is ~15 req/hr **per IP — dev and prod share it**, so don't leave a dev backend polling launches (use fixture mode), and a 429 must be retried slowly (the launches collector overrides `backoff_start`/`backoff_max` to 15–60 min; the default 5s..300s retry loop alone would exceed the budget and never recover). NHC storm geometry comes from per-storm KMZ products (zipped KML, stdlib-parsed in `collectors/hurricanes.py`), re-fetched only on advisory-number change.

## Appliance quirks (matter for any display work)

- **No emoji fonts** on the device — all icons must be inline SVG (`frontend/display/icons.ts`, `stroke="currentColor"`).
- The watchdog (`deploy/watchdog.sh`, timer every minute) restarts the backend on failed health checks or collectors listed in `stuck` for 3 checks, and the kiosk when `display_clients` stays 0. Its unit runs it through `/bin/bash`: a commit from a checkout with `core.fileMode=false` once dropped the exec bit and the watchdog failed with 203/EXEC every minute from June to September unnoticed.
- Chromium is the **snap** (`/snap/bin/chromium`); there is no `/usr/bin/chromium`. Snap confinement redirects `/tmp` writes — headless screenshots must target `$HOME`.
- `kiosk.service` needs the PAM/logind/seat0 setup and the udev rule in `deploy/` (the touch controller exposes a mouse node that otherwise draws a cursor).
- Config lives in SQLite (`data/ticker.db`), seeded once from `config/defaults.yaml`; live edits go through `PUT /api/config`, which restarts collectors and broadcasts to all clients. Existing DBs don't get new default keys — code must default gracefully.
- Secrets in `.env` (prod: `/opt/edge-ticker/.env`, root-owned — editing the dev checkout's `.env` does not affect prod).

## Verification workflow (established pattern)

1. Run the dev backend on `:8081` — in fixture mode for anything display-side — and probe with short Python WS/HTTP scripts (`websockets`/`httpx` are in the venv). `scripts/layout_audit.py` refuses to run against a non-fixture backend (it rewrites appearance/rotation config per combination); it flags elements that a clipping ancestor cuts *part-way* (wholly hidden is fine) and panes stuck on "Waiting for …"/"couldn't be drawn". It does not catch overlap between siblings (e.g. the mosaic clock chip over content) — look at `--shots` for that.
2. Visual checks: `/snap/bin/chromium --headless=new --window-size=2560,720 --virtual-time-budget=9000 --screenshot=$HOME/... http://127.0.0.1:8081/display`; for interactions, attach CDP (`--remote-debugging-port`) and dispatch **pointer** events (`gestures.ts` ignores synthetic `.click()`).
3. Debug hooks on the display window for injecting state: `__rotshow(id)` (jump+pin a module into pane 0), `__modfake(id, stage)` (replace any payload), plus side-effect-aware fakes `__sportsfake(games)`, `__fantasyfake(stage)`, `__launchfake(stage)`, `__adsbfake(stage)`, and event triggers `__celebrate(event)`, `__fantasyevent(event)`, `__scorechip(game)`, `__weatheralert(alert)`, `__hatest(entity, state, name)`, `__starshiptest()`, plus `__hafake(states, status?)` (opens the swipe-up HA overlay against injected entity states — the only way to exercise it here, since the dev `.env`'s `HA_URL=homeassistant.local` does not resolve on this box; only prod reaches HA). Canned display tests also exist as control actions (`celebrate_test`, `weather_alert_test`, `starship_test`) with buttons in the admin System tab.
4. Mutate the dev config via `PUT /api/config` for the scenario (rotation order, theme/layout, followed teams) and restore it afterward.
5. To inspect the **live kiosk** (not dev `:8081`) it has no DevTools port by default — add one with a `/etc/systemd/system/kiosk.service.d/*.conf` drop-in that re-declares `ExecStart` with `--remote-debugging-port=9222` (binds localhost only), `daemon-reload` + `restart kiosk`, then attach CDP to `:9222`: the page exposes the same debug hooks plus `Page.captureScreenshot` of the *real panel*. Delete the drop-in to revert. Confirmed this way: a live `__celebrate(baseballEvent)` renders fine on the kiosk and fires **zero** stray `pointerdown`s (the udev mouse-ignore rule holds) — so "no celebration" was the cooldown + wrong-scorer, not the display.
6. Scripting the snap chromium from a shell: `export XDG_RUNTIME_DIR=/run/user/$(id -u)` (else it dies silently, exit 144), put `--user-data-dir` under `~/snap/chromium/common/` (AppArmor denies arbitrary paths), and spawn it as a **foreground child** — a background job gets killed. `sudo` cannot authenticate from the tool shell **or** from the `!` prompt prefix — both fail with "a terminal is required to authenticate", there is no NOPASSWD rule in `/etc/sudoers.d`, and `/opt/edge-ticker` is root-owned end to end. Privileged steps (deploy, kiosk restart) have to be run by the user in a real terminal; pre-authenticating with `sudo -v` elsewhere doesn't help either, since Ubuntu keeps per-TTY sudo timestamps.
